04 · Dépannage

Quand quelque chose ne marche pas

Les erreurs rencontrées pendant le projet, avec la piste à suivre pour chacune.

PHP et Composer

Erreur « Class Dotenv\Dotenv not found »

L'autoloader de Composer n'est pas chargé, ou la bibliothèque n'est pas installée. Vérifie que le fichier PHP commence bien par le chargement de vendor/autoload.php, puis relance l'installation.

composer install
composer dump-autoload
Composer : « fichier verrouillé » sous Windows

Un autre programme utilise un fichier du dossier vendor (éditeur, antivirus, serveur PHP en cours). Arrête le serveur PHP, ferme l'éditeur, puis relance la commande. En dernier recours, supprime le dossier vendor et réinstalle.

rmdir /s /q vendor
composer install
Page blanche en PHP

PHP cache les erreurs. Démarre le serveur en les affichant :

php -d display_errors=1 -d error_reporting=E_ALL -S 127.0.0.1:8200
404 après avoir remplacé le dossier du backend sur le serveur FTP

Vérifie que le nouveau dossier a exactement le même nom et le même emplacement que l'ancien, qu'il contient bien les fichiers index / api attendus, et que le .env a été envoyé aussi (il est souvent exclu par défaut).

« 403 Forbidden nginx » en appelant l'API en local

La page vient d'un serveur nginx, pas du serveur PHP intégré : l'adresse appelée n'est probablement pas celle de ton serveur local. Teste d'abord l'adresse du serveur lancé avec php -S.

curl -i http://127.0.0.1:8200/api/insert.php

Nuxt et exports

Le fichier export .xlsx téléchargé contient du HTML

La requête n'a pas atteint l'API : c'est la page de l'application Nuxt qui est revenue. Ouvre le fichier dans un éditeur de texte : s'il commence par <!DOCTYPE html>, vérifie l'adresse appelée (NUXT_PUBLIC_API_BACKEND, baseURL) et la méthode HTTP.

Côté PHP, contrôle aussi que l'en-tête de réponse indique bien un fichier Excel et que rien n'est affiché avant l'envoi du fichier (pas d'espace ni de var_dump oublié).

Le .env fonctionne en développement mais pas une fois déployé

Pour un site Nuxt généré, la valeur du .env est lue au moment de la génération. Définis NUXT_PUBLIC_API_BACKEND avant de lancer npm run generate, puis déploie le résultat.

Git et GitHub

git push renvoie une erreur 403

Tu n'as pas les droits d'écriture sur le dépôt avec le compte utilisé. Vérifie que ton compte est bien contributeur du dépôt, que tu es connecté avec le bon compte, ou utilise un jeton d'accès personnel à la place du mot de passe.

git remote -v
git config user.name

KITs et ePigeon

Le style est cassé après l'envoi par ePigeon (mais correct en local)

Deux causes déjà rencontrées :

1. Les attributs style="" contenant des entités &quot; sont cassés. Utilise des apostrophes simples dans les noms de police : font-family: 'Assistant', sans-serif.

2. Les fonds en linear-gradient(…rgba(…)) ne passent pas. Utilise une couleur unie en hexadécimal.

Le KIT ne s'adapte pas sur mobile

Certains clients de messagerie ignorent les media queries (notamment Gmail avec des comptes non-Google). Pour limiter le problème, privilégie des colonnes qui se replient seules et des éléments à largeur flexible (max-width, width: 100%) en plus des media queries.
